# 03 — Database Schema (Firestore)

## Overview

Firestore is a NoSQL document database. Data is organized into **collections** containing **documents**. Each document is a JSON-like object.

---

## Collection: `users`

Stores both donors and distributors. Role field distinguishes them.

```javascript
users/{userId}   // userId = Firebase Auth UID
{
  // Auth
  phone:    "+8801XXXXXXXXX",       // unique
  role:     "donor" | "distributor",

  // Common
  name:         "Alif Catering",
  address:      "42 Gulshan Avenue, Dhaka",
  location:     new GeoPoint(23.7925, 90.4078),
  phone:        "+8801XXXXXXXXX",
  profilePhoto: "gs://..." | null,
  isVerified:   false,
  createdAt:    Timestamp,

  // ── Donor-specific ──
  businessType: "restaurant" | "hotel" | "catering" | "bakery" | "supermarket" | "event_hall" | "other",
  operatingHours:  "10:00-23:00",
  preferredPickupWindow: "22:00-00:00",

  // ── Distributor-specific ──
  orgType:           "orphanage" | "shelter" | "madrasa" | "mosque" | "community_kitchen" | "ngo" | "other",
  peopleServed:      150,
  hasVehicle:        false,
  preferredFoodTypes: ["cooked", "raw", "packaged"],
  pickupRadius:      5,                            // km
}
```

### Firestore Security Rule (users)

```javascript
match /users/{userId} {
  allow read: if request.auth != null;
  allow write: if request.auth != null && request.auth.uid == userId;
}
```

## Collection: `foodListings`

Each document represents a single food donation post.

```javascript
foodListings/{listingId}     // auto-generated by Firestore
{
  // Donor reference
  donorId:        "userId123",
  donorName:      "Alif Catering",
  donorPhone:     "+8801XXXXXXXXX",

  // Food details
  title:          "Chicken Biryani - 5kg",
  category:       "cooked" | "raw" | "packaged" | "bakery" | "fruits_veg" | "other",
  quantity:       5,
  quantityUnit:   "kg",
  photoURLs:      ["gs://..."],                  // up to 3 photos
  preparedAt:     Timestamp,                     // when food was cooked/packaged
  pickupDeadline: Timestamp,                     // auto-expire after this

  // Location
  location:       new GeoPoint(23.7925, 90.4078),
  address:        "42 Gulshan Avenue, Dhaka",

  // Status
  status:         "available" | "claimed" | "confirmed" | "picked_up" | "completed" | "cancelled" | "expired",

  // Other
  specialNotes:   "Needs cold storage. Vegetarian.",
  createdAt:      Timestamp,
  updatedAt:      Timestamp,
}
```

### Indexes Required

| Collection | Fields | Type |
|------------|--------|------|
| foodListings | `status` Ascending + `location` | Composite (for showing available food on map) |

In Firebase Console > Firestore > Indexes, create:

```
Collection: foodListings
  Fields: status (Ascending), location (Ascending)
```

### Security Rules

```javascript
match /foodListings/{listingId} {
  allow read: if request.auth != null;
  allow create: if request.auth != null && request.resource.data.donorId == request.auth.uid;
  allow update: if request.auth != null && resource.data.donorId == request.auth.uid;
  allow delete: if request.auth != null && resource.data.donorId == request.auth.uid;
}
```

## Collection: `claims`

Tracks the lifecycle of a distributor claiming a food listing.

```javascript
claims/{claimId}     // auto-generated
{
  listingId:      "listing123",
  donorId:        "user123",
  distributorId:  "user456",

  status:         "pending" | "confirmed" | "rejected" | "picked_up" | "completed",

  // Timestamps
  claimedAt:      Timestamp,           // when distributor claimed
  respondedAt:    Timestamp | null,    // when donor confirmed/rejected
  pickedUpAt:     Timestamp | null,    // when distributor picked up
  completedAt:    Timestamp | null,    // when donor marked complete
  cancelledAt:    Timestamp | null,

  createdAt:      Timestamp,
  updatedAt:      Timestamp,
}
```

### Security Rules

```javascript
match /claims/{claimId} {
  allow read: if request.auth != null &&
    (resource.data.donorId == request.auth.uid ||
     resource.data.distributorId == request.auth.uid);
  allow create: if request.auth != null &&
    request.resource.data.distributorId == request.auth.uid;
  allow update: if request.auth != null &&
    (resource.data.donorId == request.auth.uid ||
     resource.data.distributorId == request.auth.uid);
}
```

## Collection: `notifications`

Stores push notification records for in-app notification list.

```javascript
notifications/{notificationId}    // auto-generated
{
  userId:       "user123",
  title:        "New Claim",
  body:         "Alif Catering confirmed your pickup request",
  type:         "claim_received"
              | "claim_confirmed"
              | "claim_rejected"
              | "pickup_completed"
              | "pickup_confirmed"
              | "new_listing",
  listingId:    "listing123" | null,
  claimId:      "claim123" | null,
  isRead:       false,
  createdAt:    Timestamp,
}
```

### Security Rules

```javascript
match /notifications/{notifId} {
  allow read: if request.auth != null && resource.data.userId == request.auth.uid;
  allow write: if request.auth != null && request.resource.data.userId == request.auth.uid;
}
```

## Data Relationships (NoSQL Style)

```
users ──< foodListings    (donor has many listings)
users ──< claims          (distributor has many claims)
foodListings ──< claims   (listing has one or more claims? NO — enforce one claim per listing via app logic)
```

**One claim per listing rule:** Before a distributor can claim, check if `claims` has any doc where `listingId == X` && `status != "rejected" && status != "cancelled"`. If yes, listing is unavailable.

---

## Offline Strategy

Firestore enables offline persistence by default on Android. Data reads come from local cache when offline and sync when reconnected. This is critical for Bangladesh where mobile data may be intermittent.
